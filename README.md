# carmelom.github.io

Personal landing page + CV. Static site generated by a small Python
`build.py` that reads YAML/Markdown sources and renders Jinja2 templates.

## Editing content

| Section              | File                              |
| -------------------- | --------------------------------- |
| Bio narrative        | `content/bio.md`                  |
| Education            | `data/education.yaml`             |
| Scientific career    | `data/career.yaml`                |
| Teaching             | `data/teaching.yaml`              |
| Publications         | `data/publications.yaml`          |
| Conferences          | `data/conferences.yaml`           |
| Outreach             | `data/outreach.yaml`              |
| Contact links        | `templates/partials/contact.html` |

Every entry has a stable slug `id` used for cross-referencing and for
profile filters.

## Build

The project uses [uv](https://docs.astral.sh/uv/) for environment
management — everything (Python + dependencies, including WeasyPrint)
lives in a local `.venv/`. Nothing leaks into your global Python.

```sh
make install      # uv sync -> .venv/
make build        # uv run python build.py    -> ./site/
make serve        # auto-reloading dev server at http://localhost:9997
make pdf          # generate cv.pdf for every profile
make clean
```

`make serve` runs `serve.py`, which builds once, serves `site/`, watches
the source dirs, rebuilds on any change, and injects a livereload script
that refreshes the browser automatically.

All Python dependencies — including WeasyPrint and the livereload
server — live in `.venv/`. Nothing is installed system-wide.

WeasyPrint relies on Pango/Cairo/GLib at the C level. On Linux/macOS
those libs are typically already present (or one `apt install` away).
On Windows they aren't, so the PDF path goes through WSL.

### Generating PDFs on Windows (via WSL)

One-time bootstrap from Windows (installs uv + WeasyPrint apt deps
inside WSL; will prompt for sudo):

```sh
make setup-wsl
```

Then, whenever you need PDFs:

```sh
make pdf-wsl
```

This invokes WSL on the same checkout, builds a separate Linux venv at
`.venv-linux/` (so your Windows `.venv/` is untouched), and produces
`site/cv*.pdf` directly on the Windows filesystem.

You only need this when you specifically want WeasyPrint-rendered
PDFs. For everyday previews, `make serve` + Ctrl+P on the `/cv` page
produces a faithful PDF too, thanks to the WYSIWYG print stylesheet.
CI always produces authoritative PDFs as workflow artifacts.

## CV variants (profiles)

Drop a YAML file in `profiles/`:

```yaml
# profiles/academic.yaml
name: academic
sections:
  - id: education
  - id: career
  - id: publications
    filter:
      since: 2018
      tags_any: [cold-atoms, trapped-ions]
  - id: teaching
```

Then `uv run python build.py --profile=academic --pdf` produces
`cv-academic.pdf`. Supported filter keys: `since` (year),
`exclude_ids`, `tags_any`, `contribution_any`.

## Deployment

GitHub Actions builds the site and publishes via
`actions/deploy-pages`. PDFs are uploaded as workflow artifacts only —
they are not served from the site.

Set the repo's Pages source to **GitHub Actions** (Settings → Pages).
